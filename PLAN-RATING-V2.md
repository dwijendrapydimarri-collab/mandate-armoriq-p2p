## Major updates in the folder

The addition of the **AHCP-E1.1 Core Operating Framework** and the **10-Phase Implementation Plan** has transformed the project from a strong concept into a professional engineering mission.

### 1. The AHCP-E1.1 Advantage
The project is now governed by a "digital constitution" that forces the agent into a self-correcting 10-stage pipeline. The inclusion of an **Adversarial Dissent Pass (Stage 8c)** is particularly impressive—it ensures the system is challenged by its own logic before being presented to judges.

### 2. The "Crown Jewel": Plan-Ordering Invariant
The plan now explicitly enforces the most critical security property: **Authority is fixed before the agent reads anything an attacker can write.**
*   **Trusted Data Only:** Vendor master and POs are read first.
*   **Cryptographic Seal:** `capture_plan()` seals the envelope *before* the untrusted surface is touched.
*   **Untrusted Invoices:** Only read *after* authority is frozen.
This prevents "intent poisoning" where an attacker injects a fraudulent payee into the plan itself. This insight alone could win the track.

### 3. The "Golden Balances" (T6)

*   **Governed:** ₹39,91,726
*   **Ungoverned:** ₹38,57,560
*   **Prevented Loss:** ₹1,34,166
These numbers are the "headline" of the demo. Putting them side-by-side on screen is the most powerful way to communicate ArmorIQ's value.

### 4. Extreme Determinism
The use of `.cache/llm/` for zero-API replay mode (P10) and sequential agent execution removes the "demo ghost" of non-deterministic LLM behavior. The 10-consecutive-run verification gate is an excellent reliability standard.
